---
title: Use StackBlaze from your AI coding tool
description: Give Cursor, Claude Code, Codex, VS Code (Copilot), Windsurf or OpenCode the StackBlaze skill and MCP server, so your agent can deploy and operate your apps.
---

The StackBlaze CLI can set up your AI coding tool in one command. It installs:

- **The StackBlaze skill**: instructions that teach the agent how to use the `stackblaze` CLI and MCP tools (deploying apps, linking a project, reading logs, managing add-ons).
- **The StackBlaze MCP server**: `https://mcp.stackblaze.cloud/mcp`, which the agent calls with your API token.

You need the [CLI installed and signed in](/cli/install) first.

## Set up every tool at once

```sh
stackblaze setup agent -y
```

It configures the AI coding tools it finds on your machine (`--agent all` is the default; pass `--agent cursor`, `claude`, `codex`, `vscode`, `windsurf`, `opencode` or `copilot` to pick one). When we ran it on a machine with none of them installed, it set up Cursor:

```text
Configuring StackBlaze agent tooling (cursor)
OK Installed skill → ~/.agents/skills/stackblaze/SKILL.md
OK Installed skill → ~/.cursor/skills-cursor/stackblaze/SKILL.md
OK Configured stackblaze MCP for Cursor → ~/.cursor/mcp.json
OK Agent setup complete. Restart the editor if MCP was already loaded.
```

The MCP entry it writes uses the API token your CLI signed in with. Restart the editor if it was already running.

## Set up the MCP server for one tool

```sh
stackblaze setup mcp --ide claude
```

`--ide` takes `cursor` (the default), `claude`, `codex`, `vscode` (or `copilot`), `windsurf` or `opencode`. The `stackblaze` entry is merged into that tool's config file; other servers in it are kept:

| Tool | File |
|---|---|
| Cursor | `~/.cursor/mcp.json` |
| Claude Code | `~/.claude.json` |
| Codex | `~/.codex/config.toml` (`[mcp_servers.stackblaze]`) |
| VS Code (Copilot) | `mcp.json` in your VS Code user folder |
| Windsurf | `~/.codeium/windsurf/mcp_config.json` |
| OpenCode | `~/.config/opencode/opencode.json` |

### Configure it by hand

Add `--print` to print the snippet instead of writing the file. The token is shown as a placeholder. For Claude Code:

```sh
stackblaze setup mcp --ide claude --print
```

```json
{
  "mcpServers": {
    "stackblaze": {
      "type": "http",
      "url": "https://mcp.stackblaze.cloud/mcp",
      "headers": {
        "Authorization": "Bearer <STACKBLAZE_TOKEN>"
      }
    }
  }
}
```

For Codex, the token is read from the `STACKBLAZE_TOKEN` environment variable:

```toml
[mcp_servers.stackblaze]
url = "https://mcp.stackblaze.cloud/mcp"
bearer_token_env_var = "STACKBLAZE_TOKEN"
```

Replace `<STACKBLAZE_TOKEN>` with an API token. The CLI suggests creating one per tool, for example:

```sh
stackblaze tokens create claude-mcp
```

The MCP server rejects requests without a token.

## Install only the skill

```sh
stackblaze setup skills
```

`--agent` takes `cursor`, `claude` or `all` (the default). On our test machine it wrote:

```text
OK Installed skill → ~/.agents/skills/stackblaze/SKILL.md
OK Installed skill → ~/.cursor/skills-cursor/stackblaze/SKILL.md
```
