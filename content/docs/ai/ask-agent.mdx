**Ask Agent**, in the header on every page, opens the assistant in a side panel. It can look at your projects and apps to answer questions about them, and change them for you. Click the button again, or the panel's close button, to hide it.

Ask Agent operates StackBlaze for you. It isn't the same as an [AI agent](/ai/agents), which is a service you deploy that answers your own users with your instructions. To use StackBlaze from your own AI coding tool, see [Use StackBlaze from your AI coding tool](/ai/coding-tools).

## It knows the page you're on

Each message carries the page you're on: the project, environment, service or add-on open in the dashboard. Questions like "why did the last deploy fail?" then work without naming the service. An app or add-on you attach with `@` is added to that.

## Start it from a page

Two buttons send a ready-made question to Ask Agent and open the panel:

- **Check performance**, on a service's **Metrics** tab, asks "Why is @*service* slow?" with the service attached. A toast says **Asked the agent. The answer appears in the chat panel.** The agent looks at the service's settings, metrics, logs and add-ons, then answers. See [Metrics](/observe/metrics#check-performance-and-monitoring).
- **Diagnose**, on an add-on deployment that failed, asks why that deploy failed, with the add-on attached.

We clicked **Check performance** on a small nginx service. The agent found no cause on the server side: response time, CPU and memory were normal, with no errors or restarts. It asked which requests were slow and where we measured from.

<Screenshot id="ask-agent/perf-answer" alt="The answer to Why is @nginx-unprivileged-mi0u slow?: response time, CPU, memory, errors and traffic all normal, and what it needs to narrow it down" />

## It asks before risky actions

Before some actions, the agent stops and shows a red card with what it's about to do. Below the message box, **Choose an option** offers the action and **Cancel** (**Keep unchanged**). Press **1** or **2**, or click one. It asks first before it:

- deletes a service or a project (deleting a project deletes every service in it),
- restarts a service ("Its pods will roll over."),
- scales a service,
- resets an add-on's password,
- opens a support ticket for you.

We asked it to restart a service. It showed **nginx-unprivileged-mi0u — restart pending** and **Restart nginx-unprivileged-mi0u in github-demo-kpw0/dev. Its pods will roll over.**

<Screenshot id="ask-agent/confirm-card" alt="The confirmation card: restart pending, with Choose an option: 1 Restart, 2 Cancel Keep unchanged" />

We chose **Cancel**. The agent said the restart was declined, changed nothing and didn't retry it.

<Screenshot id="ask-agent/confirm-declined" alt="After Cancel: The restart was declined, so I haven't changed anything and won't retry it." />

A card that gets no answer for a minute counts as **Cancel**. When you ask for several deletes at once, like every service in a project, one card lists them all.

<Callout type="warn">
Deleting a service also deletes its volumes and the databases made only for it. Their data is gone. Add-ons shared by the environment stay. The agent can be wrong: read what it proposes before you approve it, above all in production.
</Callout>

## What it can change

- **It acts as you.** It can see and change only what your role allows. A member with read-only access can ask questions, but changes are refused.
- **Databases**: it can look inside a database add-on (tables, columns, a few rows). In the **production** environment it only reads. In other environments it can also write, if your role can change services.

## Where your conversations are kept

Conversations are kept in your browser, for your account. It keeps your 50 newest; older ones drop off. They don't follow you to another browser or computer.

## From the terminal

`stackblaze agent` is the same assistant in your terminal. Without a prompt it starts a chat; with one it answers once and exits:

```sh
stackblaze agent "How many instances is nginx-unprivileged in github-demo-kpw0 dev running? One sentence."
```

```text
nginx-unprivileged in github-demo-kpw0/dev is running 1 instance (1 web pod, ready, 0 restarts), with autoscaling set to min 1 and max 3 based on CPU.
```

- `-a <app>` scopes the conversation to a service.
- `--json` prints the answer and the tools it called as JSON, for scripts. It needs a prompt.
- `--list` lists the chats saved on this machine, and `--thread-id <id>` picks one up again.

In a chat, `/help` lists the commands: `/project`, `/environment` (or `/env`), `/app` and `/addon` set the scope, `/context` shows it, `/clear` starts over and `/exit` ends the chat.

A risky action asks **Confirm …? (y/N)**. When the CLI has no terminal to ask in, like in a script, it declines. We asked it to restart a service from a script, and it printed `auto-declining confirmation for "restart_app" (non-interactive; pass --yes to allow)`. `-y` (`--yes`) approves them all, so use it with care.

Every option is in the [CLI reference](/cli/reference/agent).
