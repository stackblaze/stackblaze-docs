---
title: Reach your agent
description: Put your AI agent on a website, call it from your code with an API key, start it from a webhook or on a schedule, and read every conversation in Sessions.
---

Besides the team chat page, an [AI agent](/ai/agents) can be reached four ways: a chat bubble on your website, its API, a webhook and a schedule. You set them up in the agent's sheet, under **Agent** → **Triggers**, which has four tabs: **Time**, **Webhook**, **API** and **Widget**. Every conversation, whatever started it, shows in **Agent** → **Sessions**.

Click the agent's card on the canvas to open its sheet.

<Callout>
API keys and webhooks are saved as soon as you create or revoke them, and the agent restarts to pick them up. This takes about a minute. Until it has restarted, a new key is refused and a revoked key or webhook still works. Schedules and the widget are staged: click **Stage changes**, then deploy them from the canvas like any other change.
</Callout>

## Call it from your code

<Steps>

<Step>

### Create an API key

Go to **Agent** → **Triggers** → **API**. Type what the key is for (for example **Website**) and click **Create key**.

<Screenshot id="ai-agent/ch-api-empty" alt="API keys: No API keys yet, a label field and Create key" />

The key is shown once, with **Copy** and **Done**: copy it now, because it is not shown again. The list then shows the start of the key, its label, the day it was created and **Revoke**.

<Screenshot id="ai-agent/ch-api-key" alt="Copy this key now. It is not shown again. The key is hidden here; below it, the key Docs test with Revoke" />

</Step>

<Step>

### Start a chat

The agent's address is under its name at the top of the sheet. Send the key as a bearer token. `POST /v1/chats` starts a chat and returns its id:

```bash
curl -X POST https://<agent-address>/v1/chats \
  -H "Authorization: Bearer $AGENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

```json
{"chat_id":"16daab6d-01a3-49a0-baa3-4108555339a1"}
```

Without a valid key the answer is `401` with `{"error":"Missing or invalid credentials."}`.

</Step>

<Step>

### Send a message

Post the message to the chat. The call returns when the agent has answered:

```bash
curl -X POST https://<agent-address>/v1/chats/<chat_id>/messages \
  -H "Authorization: Bearer $AGENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"message":"Read faq.md in your knowledge folder, then tell me: do you sell decaf?"}'
```

```json
{"chat_id":"94f0c149-…","reply":"Yes, I do sell decaf. The Night Owl blend is Swiss Water decaf.","usage":{"input":3733,"output":56,"cached":0},"model":"gateway/Qwen/Qwen3-4B","error":null}
```

The reply comes with the tokens it used (`usage`) and the model that answered. Send more messages to the same `chat_id` to continue the conversation. A body without `message` is refused with `"message" is required.`

`GET /v1/chats/<chat_id>` with the same key returns the chat: its channel (`api`), turns, tokens and every event, including the tools the agent used.

</Step>

<Step>

### Revoke the key

Click **Revoke** next to the key and confirm **Revoke sbag_…? Anything using it stops working.** A toast says the key is revoked. Once the agent has restarted, calls with that key get `401`.

<Screenshot id="ai-agent/ch-api-revoked" alt="API keys after revoking: No API keys yet" />

</Step>

</Steps>

## Start it from a webhook

A webhook lets another service start a chat: the agent gets the request body as its message.

<Steps>

<Step>

### Create a webhook

Go to **Agent** → **Triggers** → **Webhook**. Type what calls it (for example **GitHub**) and click **Create webhook**.

You see its **URL** and **Secret**, each with **Copy**, and a `curl` example with **Copy example**. The secret is shown once: copy it now.

<Screenshot id="ai-agent/ch-webhook-new" alt="Copy the secret now. It is not shown again. The webhook URL, the hidden secret and a curl example" />

</Step>

<Step>

### Call it

Send a `POST` to the URL with the secret as a bearer token and any JSON body:

```bash
curl -X POST 'https://<agent-address>/v1/hooks/<id>' \
  -H 'Authorization: Bearer <secret>' \
  -H 'Content-Type: application/json' \
  -d '{"event":"order.refund_requested","order":"A-1042"}'
```

The webhook answers at once with `202` and the new chat's id, `{"chat_id":"…"}`, and the agent works on it in the background. Its message is `A webhook "<id>" was received.` followed by the body. The answer is in **Sessions**, on the **Webhook** channel.

A wrong secret gets `401` with `{"error":"Missing or invalid webhook secret."}`.

</Step>

<Step>

### Revoke it

The list shows each webhook's label, its URL with **Copy**, the day it was created and **Revoke**. Click **Revoke** and confirm **Revoke the webhook …? Calls to it stop working.** Once the agent has restarted, the URL answers `404` with `{"error":"No such webhook."}`.

<Screenshot id="ai-agent/ch-webhook-list" alt="Webhooks: docs-test with its URL, Copy, the date and Revoke" />

</Step>

</Steps>

## Run it on a schedule

A schedule sends the agent a message at set times, like a daily report. Each run is a new chat in **Sessions**.

<Steps>

<Step>

### Add a schedule

Go to **Agent** → **Triggers** → **Time** and click **Add schedule**. A schedule has:

- **When**: a cron expression with five fields (minute, hour, day, month, weekday). It starts at `0 9 * * 1-5`. **Presets** fills in **Every hour** (`0 * * * *`), **Every day at 09:00** (`0 9 * * *`), **Weekdays at 09:00** (`0 9 * * 1-5`) or **Every Monday at 09:00** (`0 9 * * 1`).
- **Time zone**: the zone the times are in.
- **On**: turn it off to keep the schedule without running it.
- The message the agent gets, up to 4,000 characters.

<Screenshot id="ai-agent/ch-schedule-presets" alt="The Presets menu: Every hour, Every day at 09:00, Weekdays at 09:00, Every Monday at 09:00" />

Under the message, the row shows the next run, for example **Next run: Tue, Nov 24, 08:29 PM UTC**. An expression without five fields shows **Use 5 fields: minute hour day month weekday, like 0 9 * * 1-5.** and an empty message shows **Write the message the agent gets.**

<Screenshot id="ai-agent/ch-schedule" alt="A schedule: 29 20 * * * in UTC, On, the message and Next run" />

</Step>

<Step>

### Deploy it

Click **Stage changes**. The toast says **Agent settings staged**. Close the sheet, click **Commit 1 change** on the canvas and **Deploy 1 change**.

At the set time the run shows in **Sessions** on the **Schedule** channel, with the message and the agent's answer.

<Screenshot id="ai-agent/ch-session-open" alt="Sessions filtered to Schedule: the scheduled run with its message, the answer and its tokens" />

</Step>

<Step>

### Remove it

Click **Remove** on the schedule, then **Stage changes**, and commit and deploy as before.

</Step>

</Steps>

## Put it on your website

The widget is a chat bubble for the visitors of your site.

<Steps>

<Step>

### Turn on the widget

Go to **Agent** → **Triggers** → **Widget** and turn on **Website widget**.

<Screenshot id="ai-agent/ch-widget-off" alt="Website widget, off" />

Visitors are anonymous, so while the widget is on, the agent has no shell or file-editing tools (**bash**, **edit** and **write**), and its integrations are off. **Integrations** then says **Integrations are off while the website widget is on: a visitor could talk the agent into using them.**

</Step>

<Step>

### List your sites

Under **Sites that may embed it**, type the address of each site that shows the bubble, and click **Add site** for another (up to 20). **Remove** takes a site off the list.

Give the address only: `https://` and the host, with a port if it has one. `http://` works only for `localhost`. The field explains what is wrong:

- `acme.com`: **Enter a site address, like https://acme.com.**
- `https://acme.com/shop`: **Only the site address: no path, like https://acme.com.**

<Screenshot id="ai-agent/ch-widget-on" alt="Website widget on, with http://localhost:8765 as the site, Add site and The embed code shows here once the widget is saved" />

Click **Stage changes**, then commit and deploy from the canvas.

</Step>

<Step>

### Paste the embed code

Once the change is deployed, **Embed code** shows the tag, with **Copy**:

```html
<script src="https://<agent-address>/widget.js" async></script>
```

Paste it before `</body>` on the pages that should show the bubble.

<Screenshot id="ai-agent/ch-widget-snippet" alt="The embed code: a script tag loading widget.js from the agent, with Copy" />

The bubble opens a chat panel with the agent's name, a **Type a message…** box and **Send**. On a site that is not on the list, the panel refuses to load.

<Screenshot id="ai-agent/ch-widget-chat" alt="A test page with the widget open: a question and the agent's answer" />

To turn the widget off, turn off **Website widget**, stage the change and deploy it.

</Step>

</Steps>

## Read the sessions

**Agent** → **Sessions** lists every conversation, from every channel, newest first. Each row shows the first message, the channel, the number of turns and how long ago it was. **Refresh** reloads the list.

<Screenshot id="ai-agent/ch-sessions" alt="Sessions: chats from the Widget, Schedule, Webhook and API channels" />

The list shows **All channels**, or one of them: **Team chat**, **API**, **Widget**, **Webhook**, **Schedule** or **Eval**.

<Screenshot id="ai-agent/ch-sessions-channels" alt="The channel menu: All channels, Team chat, API, Widget, Webhook, Schedule, Eval" />

Click a chat to read it. The top line shows its channel, when it started and the tokens it used (in and out). The messages follow, with a line for each tool the agent used, such as **used read**. **Add to eval** turns the chat's first message into a test case: see [Test your agent](/ai/agents/evals).
