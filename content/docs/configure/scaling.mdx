---
title: Scaling
description: Set how many instances of a service run, let it autoscale on CPU or memory.
---

**Settings** → **Scale** holds two cards: **Scale** ("How many copies of this service run.") and **Sleep mode**.

<Screenshot id="settings/scale" alt="Scale: Autoscale Off, Instances 1, and Sleep mode Off" />

## Instances

**Instances** is the number of copies that run, set with **−** and **+**. The card says how many your plan allows, for example "Up to 10 instances on your plan." The limit per plan:

| Plan | Instances per service |
| --- | --- |
| Trial | 1 |
| Developer | 1 |
| Pro | 3 |
| Business | 10 |

<Steps>

<Step>

### Add an instance

Click **+**. The row reads **2 instances**.

<Screenshot id="settings/scale-2" alt="Instances: 2 instances" />

</Step>

<Step>

### Commit and deploy

Click **Commit 1 change**. The dialog lists **Web instances** `1` → `2`. Click **Deploy 1 change**. A minute later both instances are running and ready.

<Screenshot id="settings/scale-commit" alt="1 change to apply: Web instances 1 → 2" />

</Step>

</Steps>

## Autoscale

Turn on **Autoscale** in the **Scale** header. The fixed count is replaced by a range and the metrics to scale on:

- **Instances**: **Min** and **Max**. Both start at the current number of instances. If you set **Min** above **Max**, **Max** moves up with it.
- **Scale up when…**: **CPU** and **Memory**, each with a switch and a target in "% average utilization". Both targets start at **80**. **CPU** is switched on for you.

<Screenshot id="settings/autoscale-on" alt="Autoscale On: Min and Max, CPU above 80% on, Memory off" />

Switching on **Memory** adds a warning: "Memory-based scaling can be one-way: heap-holding runtimes (JVM, Node) rarely release memory, so instances may never scale back down."

<Screenshot id="settings/autoscale-memory" alt="Memory switched on, with the one-way scaling warning" />

With both switched off, the card says "No metric selected — autoscaling is inactive".

<Screenshot id="settings/autoscale-no-metric" alt="No metric selected — autoscaling is inactive" />

<Steps>

<Step>

### Set the range and the target

Here: **Min** `1`, **Max** `3`, **CPU** above `70`.

<Screenshot id="settings/autoscale-set" alt="Autoscale: Min 1, Max 3, CPU above 70%" />

</Step>

<Step>

### Commit and deploy

The dialog lists **Autoscaling** `off` → `on` and **Web autoscale range** `0–0` → `1–3`. Click **Deploy 1 change**. The saved service has a range of 1 to 3 instances and a CPU target of 70%.

<Screenshot id="settings/autoscale-commit" alt="1 change to apply: Autoscaling off → on, Web autoscale range 0–0 → 1–3" />

</Step>

</Steps>

## Instance size

The panel header shows the service's instance size, for example **Small**. **Settings** has no control to change it.
