```text
Usage: stackblaze metrics [options]

Show CPU/memory usage for an app (now, or history with --since)

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  --since <window>       History window: 30m, 1h, 24h, 7d (max 7d) — sparklines
                         for cpu, memory, requests, latency
  -w, --watch            Refresh the history until Ctrl-C (default window 1h)
                         (default: false)
  --interval <seconds>   Seconds between --watch refreshes (default 30)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

Without --since: the current CPU/memory of each pod. With --since: history
over the window, all pods combined, as a sparkline with now / avg / max.
--json prints the raw series (timestamps in ms); --watch --json prints one
document per refresh (NDJSON).

Examples:
  stackblaze metrics --since 24h
  stackblaze metrics --since 1h --watch
  stackblaze metrics --since 7d --json
```

### Example

Show each pod's CPU and memory now, then the last 24 hours as sparklines.

```sh
stackblaze metrics -p github-demo-gv35 -e dev -a nginx
stackblaze metrics -p github-demo-gv35 -e dev -a nginx --since 24h
```
