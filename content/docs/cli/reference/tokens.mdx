### Example

List your API tokens. Only names, prefixes and dates are shown, never the secrets. Each `stackblaze login` in a browser adds a `CLI · <date>` token:

```sh
stackblaze tokens list
```

## tokens create

```text
Usage: stackblaze tokens create [options] <name>

Create an API token in the current organization; prints it ONCE

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  --json                 Output JSON (same as -o json) (default: false)
  --expires <when>       Lifetime (30d, 12h, 2w, 1y) or a date (2027-01-31)
                         (default: "30d")
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

The token is printed once (stdout; --json: the "token" field) and cannot be
shown again. Store it straight away, e.g.:
  $ stackblaze tokens create ci --expires 90d --json | jq -r .token | gh secret set STACKBLAZE_TOKEN
```

## tokens revoke

```text
Usage: stackblaze tokens revoke|delete [options] <id>

Revoke an API token (id or name)

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  --json                 Output JSON (same as -o json) (default: false)
  -y, --yes              Skip confirmation prompt (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help
```

### Example

Revoke a token you no longer use, by its ID from `stackblaze tokens list` (a name works too when it's unique). The CLI asks first:

```sh
stackblaze tokens revoke cmww81ta7005huz01djfqp8kx
```

```text
Revoke token "CLI · 2026-11-25" (cmww81ta7005huz01djfqp8kx)? Anything using it stops working [y/N]: y
OK Revoked token CLI · 2026-11-25
```

A machine still signed in with that token is refused from then on:

```sh
stackblaze whoami
```

```text
x  Unauthorized
```
