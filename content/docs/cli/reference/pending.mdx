### Example

Stage two variables and a scale change without deploying, then see what's waiting. Staged values are never shown:

```sh
stackblaze variables set LOG_LEVEL=debug FEATURE_CHECKOUT=on --skip-deploy -p github-demo-cw8z -e dev -a shop-web-xivg
stackblaze scale web=2 --skip-deploy -p github-demo-cw8z -e dev -a shop-web-xivg
stackblaze pending list -p github-demo-cw8z -e dev -a shop-web-xivg
```

### Example

Ship everything staged for the app as one release, with a message for the deployments timeline:

```sh
stackblaze pending apply -p github-demo-cw8z -e dev -a shop-web-xivg -m "Debug logging + checkout flag, 2 instances"
stackblaze pending list -p github-demo-cw8z -e dev -a shop-web-xivg
```

## pending discard

```text
Usage: stackblaze pending discard [options]

Discard every staged change

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  -y, --yes              Skip confirmation prompt (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help
```

### Example

Drop a staged change you no longer want. Type `yes` to confirm (or pass `-y`):

```sh
stackblaze variables set LOG_LEVEL=trace --skip-deploy -p github-demo-cw8z -e dev -a shop-web-xivg
stackblaze pending discard -p github-demo-cw8z -e dev -a shop-web-xivg
```
