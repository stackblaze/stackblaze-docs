## apps scale

```text
Usage: stackblaze apps scale [options] [assignments...]

Scale web/worker instances or autoscaling (one release)

Options:
  --api-url <url>                StackBlaze API base URL (env
                                 STACKBLAZE_API_URL)
  --token <token>                API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>           Project name
  -e, --env <name>               Environment name (default: production)
  -a, --app <name>               App name
  --json                         Output JSON (same as -o json) (default: false)
  --skip-deploy                  Stage the change on the server instead of
                                 deploying it (apply later with `pending
                                 apply`) (default: false)
  -m, --message <text>           Release message shown in the deployments
                                 timeline
  -r, --replicas <n>             Instance count for --process (0–50, legacy
                                 form)
  --process <name>               Process for -r: web or worker (default: "web")
  --autoscale <process=min:max>  Enable autoscaling (repeatable), e.g. web=2:5
  --autoscale-off <process>      Disable autoscaling for a process (repeatable)
  -o, --output <format>          Output format: text or json (choices: "text",
                                 "json")
  -h, --help                     Print help

Examples:
  $ stackblaze scale web=3                  run 3 web instances
  $ stackblaze scale web=2 worker=1         both processes, one release
  $ stackblaze scale --autoscale web=2:5    autoscale between 2 and 5 web instances
  $ stackblaze scale --autoscale-off web    back to a fixed instance count
  $ stackblaze scale -r 0 --process worker  legacy single-process form

Instance counts are checked against your plan's per-service limit. Use
--skip-deploy to stage the change and ship it later with other staged changes.
```

### Example

Turn on autoscaling between 1 and 3 web instances, then go back to a fixed single instance.

```sh
stackblaze apps scale -p github-demo-cw8z -e dev -a hello-web --autoscale web=1:3 -m "Autoscale web"
stackblaze apps scale -p github-demo-cw8z -e dev -a hello-web --autoscale-off web web=1
```

```text
OK Scaled github-demo-cw8z/dev/hello-web web → autoscaling 1–3
OK Scaled github-demo-cw8z/dev/hello-web web → 1 instance(s) (was 2), autoscaling off
```

## apps create

```text
Usage: stackblaze apps create [options] [name]

Create an app (docker image or git repo)

Options:
  --api-url <url>            StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>            API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>       Project name
  --phase <name>             Environment name (default: production)
  -a, --app <name>           App name
  --json                     Output JSON (same as -o json) (default: false)
  --mode <mode>              docker or git (default: docker with --image, git
                             with --repository) (choices: "docker", "git")
  --name <name>              App name (or pass it positionally)
  --image <ref>              Docker image, e.g. nginx:1.27 (docker mode)
  --tag <tag>                Image tag when --image has none (default: latest)
  --repository <url>         Git URL (git mode)
  --branch <name>            Git branch (default: "main")
  --buildstrategy <s>        buildpacks, dockerfile, railpack, or plain
  --build-context <dir>      Mono-repo build context
  --dockerfile-path <path>   Dockerfile path
  --port <n>                 Container port (docker: default = the image EXPOSE
                             port)
  --worker                   Background worker: no port, no public URL
                             (default: false)
  --replicas <n>             Instance count (default: 1)
  --domain <host>            Custom domain
  --addon <name>             Attach addon by kind/name (repeatable)
  --env <pair>               KEY=value (repeatable)
  --healthcheck              Turn the HTTP health check on (a new version takes
                             traffic once it passes)
  --no-healthcheck           Turn the health check off (rollouts are not gated)
  --healthcheck-path <path>  Health check path, e.g. /api/health (default /;
                             turns the check on)
  --start-command <cmd>      Run this instead of the image or build's start
                             command, e.g. "node dist/main"
  --wait                     Poll until running (default: false)
  --timeout <seconds>        Max --wait time (default 600)
  -o, --output <format>      Output format: text or json (choices: "text",
                             "json")
  -h, --help                 Print help
```

### Example

Create an app from a Docker image in the `dev` environment, with its port and one variable, and wait until it is running.

```sh
stackblaze apps create hello-web -p github-demo-cw8z --phase dev \
  --image nginxinc/nginx-unprivileged:1.27-alpine --port 8080 \
  --env GREETING=hello --wait
```

```text

  github-demo-cw8z/dev/hello-web-qw6y: deploying — Waiting for hello-web-qw6y-web deployment; rolling out (Deploy 1.27-alpine): waiting for the new pod (1s elapsed)

  github-demo-cw8z/dev/hello-web-qw6y: deploying — Deployment does not have minimum availability. (1m45s elapsed)
```

## apps update

```text
Usage: stackblaze apps update [options] [name]

Update app config (branch, image, port, pod size, domain, health check, start
command, env); [name] = app

Options:
  --api-url <url>            StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>            API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>       Project name
  --phase <name>             Environment name (default: production)
  -a, --app <name>           App name
  --json                     Output JSON (same as -o json) (default: false)
  --branch <name>            Git branch
  --image <ref>              Docker image, e.g. nginx or nginx:1.27 (a bare
                             name keeps the current tag)
  --tag <tag>                Docker image tag
  --port <n>                 Container port
  -r, --replicas <n>         Web instances
  --worker-replicas <n>      Worker instances
  --podsize <name>           Pod size name from platform config
  --domain <host>            Custom domain (replaces ingress hosts)
  --buildstrategy <s>        buildpacks, dockerfile, railpack, or plain
  --build-context <dir>      Mono-repo build context
  --dockerfile-path <path>   Dockerfile path
  --healthcheck              Turn the HTTP health check on (a new version takes
                             traffic once it passes)
  --no-healthcheck           Turn the health check off (rollouts are not gated)
  --healthcheck-path <path>  Health check path, e.g. /api/health (default /;
                             turns the check on)
  --start-command <cmd>      Run this instead of the image or build's start
                             command (no Procfile commit needed)
  --no-start-command         Go back to the image or build's own start command
  --env <pair>               KEY=value (repeatable)
  -o, --output <format>      Output format: text or json (choices: "text",
                             "json")
  -h, --help                 Print help
```

### Example

Move an image app to a new tag and turn on the HTTP health check, so the new version only takes traffic once `/` answers.

```sh
stackblaze apps update hello-web -p github-demo-cw8z --phase dev \
  --tag 1.27.3-alpine --healthcheck-path /
```

```text
OK Updated github-demo-cw8z/dev/hello-web
image.tag, healthcheck.path=/, healthcheck on
```
