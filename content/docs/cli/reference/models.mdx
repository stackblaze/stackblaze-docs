## models deploy

```text
Usage: stackblaze models deploy|create [options] <model>

Deploy an AI model: a catalog id or any Hugging Face id (owner/name)

Options:
  --api-url <url>          StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>          API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>     Project name
  -e, --env <name>         Environment name (default: production)
  --json                   Output JSON (same as -o json) (default: false)
  --name <name>            Name of the model in the environment (default: a
                           generated one)
  --region <id>            Where its GPUs are rented, from `models sizes`
                           (default: the default region)
  --copies <n>             How many machines run the model and share the
                           requests (plan-limited, default 1)
  --gpu-type <name>        Pin every machine to one GPU type from `models
                           sizes` (default: any GPU of the class it needs)
  --always-on              Never sleep (billed while it runs) (default: false)
  --sleep-after <seconds>  On demand: sleep after this many seconds without
                           requests (300, 900 or 3600)
  --wait                   Poll until the model is running (default: false)
  --timeout <seconds>      Max --wait time (default 1800)
  -o, --output <format>    Output format: text or json (choices: "text",
                           "json")
  -h, --help               Print help

Examples:
  $ stackblaze models deploy Qwen/Qwen3-8B --wait
  $ stackblaze models deploy Qwen/Qwen3-8B --name chat --region eu --copies 2
  $ stackblaze models deploy Qwen/Qwen3-8B --always-on --gpu-type H200

The model decides its machine: one GPU of the class it needs, or one machine
with 2, 4 or 8 GPUs when no single GPU holds it. Before creating, the command
prints (stderr) what the model will run on, the price range of one copy per
hour and your GPU credit. A model that cannot run exits 1 with the reason.

GPU time is paid from prepaid GPU credit. The deploy is refused (exit 3)
when the credit does not cover one hour at the model's highest price: add
credit with `stackblaze billing gpu-credit add <amount>`. Models are paused
when the credit runs out.

On demand (the default) the model sleeps after that many seconds without requests
and wakes on the next request, in about a minute; asleep it is billed for its disk
only. --always-on keeps it up, billed while it runs. The server offers 300, 900
and 3600 seconds.

--wait prints the step, percent and download speed on stderr as they change
and exits 1 when the model failed or is not running within --timeout. With
--json the result is one document, with the wait under "wait". The API key
is never printed here: `stackblaze models key <name>`.
AI models may be switched off on your platform or not be part of your plan:
the command then exits 3 and says which.
```

## models key

```text
Usage: stackblaze models key [options] <name>

Print the model's API key (stdout; --json: the "key" field). No other command
prints it

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  --json                 Output JSON (same as -o json) (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

The key is a credential: the server records who read it. Use it as the
bearer token of the model's URL, e.g.:
  $ curl "$(stackblaze models url chat)/chat/completions" \
      -H "Authorization: Bearer $(stackblaze models key chat)" \
      -H 'Content-Type: application/json' \
      -d '{"model":"Qwen/Qwen3-8B","messages":[{"role":"user","content":"Hello"}]}'
```
