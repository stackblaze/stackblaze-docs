## builds logs

```text
Usage: stackblaze builds logs [options] [build]

Stream logs for a build job (latest or named build) until it finishes

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  -f, --follow           Follow live over WebSocket (lines as they are written;
                         falls back to polling on older servers) (default:
                         false)
  --ci                   Output NDJSON log lines (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

Without -f the build is watched by polling its logs every 2s. With -f the
server pushes each line as the build container writes it (fetch → build →
push → deploy), late joins replay earlier lines, and dropped connections
reconnect on their own. Exit code is 1 when the build fails.

NDJSON (--ci / --json): {"type":"build",...} state changes, {"type":"log",
"build","container","message"} lines, {"type":"error","message"} on failure.
Set STACKBLAZE_BUILD_STREAM=poll to force polling.

Examples:
  stackblaze builds logs -f              # follow the latest build
  stackblaze builds logs web-x7k2 -f     # follow a named build
  stackblaze builds logs -f --ci         # NDJSON for CI
```
