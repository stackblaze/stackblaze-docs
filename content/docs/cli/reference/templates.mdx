## templates search

```text
Usage: stackblaze templates search [options] [query]

Search or browse the template catalog

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  --category <name>      Filter by category
  -n, --limit <n>        Max results
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help
```

### Example

Find a template by what it does, then by category. The id in the first column is what `templates deploy` takes:

```sh
stackblaze templates search whiteboard
stackblaze templates search --category monitoring
```

## templates deploy

```text
Usage: stackblaze templates deploy [options] <template>

Deploy a catalog template into a project environment

Options:
  --api-url <url>         StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>         API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>    Project name
  --phase <name>          Environment name (default: production)
  -a, --app <name>        App name
  --json                  Output JSON (same as -o json) (default: false)
  --deployment-type <id>  Variant: standard or ha (default: "standard")
  --name <name>           Override deployed app name (multi-service templates:
                          the main app)
  --env <pair>            Env override KEY=value (repeatable)
  --wait                  Poll until the app is running (every app of a
                          multi-service template) (default: false)
  --timeout <seconds>     Max --wait time (default 600)
  -o, --output <format>   Output format: text or json (choices: "text", "json")
  -h, --help              Print help

A template with companion services (Supabase, Plane, n8n's worker…) is
deployed whole, in one request: the server checks the plan limits and room
for every service first, then creates them all, the main app first. If one
fails, the ones already created keep running and the command exits 3 saying
which exist. --env sets variables on the main app (and on companions that
inherit its environment).
```

### Example

Deploy the Excalidraw template into the `dev` environment as an app called `whiteboard`, and wait until it is up. The environment flag is `--phase` here:

```sh
stackblaze templates deploy excalidraw -p github-demo-cw8z --phase dev --name whiteboard --wait
```
