```text
Usage: stackblaze apply [options] <path>

Create or update resources declared in a manifest file or directory

Options:
  --api-url <url>         StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>         API token, sb_pat_... (env STACKBLAZE_TOKEN)
  --json                  Output JSON (same as -o json) (default: false)
  --continue-on-error     keep going if a resource fails (default: false)
  --confirm-phase-delete  delete environments removed from (or disabled in) a
                          project manifest even when their namespace still has
                          apps, pods or volumes (default: false)
  --force                 apply app manifests even when the app changed after
                          they were exported (otherwise refused, so an old
                          export cannot silently revert it) (default: false)
  -o, --output <format>   Output format: text or json (choices: "text", "json")
  -h, --help              Print help

May be disabled by your platform admin.

An app manifest carries the revision it was exported at. If the app changed
since, apply refuses it (exit 3) and names the fields it would change back:
export again, or re-run with --force to overwrite.

Removing or disabling an environment in a project manifest deletes its
namespace on a dedicated cluster with everything in it. While that namespace
still has apps, pods or volumes, apply refuses (exit 3) and lists them; re-run
with --confirm-phase-delete to go ahead. Moving an environment to another
cluster is refused until its old namespace is empty.
```
