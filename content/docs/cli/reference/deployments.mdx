## deployments rollback

```text
Usage: stackblaze deployments rollback [options] [deploy-id]

Roll back to an earlier deploy (its image and configuration, or a config
release); previous success if omitted

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  --build <name>         Build job name to roll back to (same as the positional
                         id)
  --image-only           Redeploy only the image tag; keep the current
                         configuration and auto-deploy (default: false)
  --wait                 Poll until the app is running after rollback (default:
                         false)
  --timeout <seconds>    Max --wait time (default 600)
  -y, --yes              Skip confirmation prompt (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

<deploy-id> is an ID from `stackblaze deployments list` (a ledger id or a
build name). A past deploy comes back in full: its image AND the
configuration it ran with, and auto-deploy turns off so the next push does
not bring the change back (add-ons, volumes, domains and plan stay as they
are). --image-only redeploys just the image tag. Config releases roll back
the configuration. Works for image apps too.

--wait --json prints ONE JSON document (the rollback with a `wait` field)
and exits 1 when the app does not come up.
```

### Example

Roll back to an earlier deploy from `deployments list` (its image and the configuration it ran with) and wait until the app is up again. Type `yes` to confirm, or pass `-y`.

```sh
stackblaze deployments rollback cmww8bms8008quz014dxaeq6m --wait -p github-demo-cw8z -e dev -a hello-web
```
