## projects create

```text
Usage: stackblaze projects create [options] [name]

Create a new project (name positionally or via -p)

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  --domain <host>        Wildcard domain for apps
  --phases <names...>    Environments to create (default: production)
  --region <slug>        Region to create the project in, from `stackblaze
                         regions list` (default: the workspace's preferred
                         region; asked when run interactively)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

--region is checked against the regions open for new projects (exit 1 with
the list when it is not one of them). Without it, an interactive run offers
the list — Enter keeps the default — and a script (or -y) leaves placement
to the server: the workspace's preferred region.

Examples:
  $ stackblaze regions list
  $ stackblaze projects create shop --region us-west-1
  $ stackblaze projects create shop -y          # no prompt, default region
```

## projects rename

```text
Usage: stackblaze projects rename [options] [display-name]

Set the name people see for a project (its ID, URLs and commands do not
change); --clear removes it

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  --clear                Remove the display name (the project ID is shown
                         again) (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

Only the display name changes (1 to 60 characters, one line): the project
ID used by -p, namespaces and URLs stays as it is and nothing is deployed.
Uses the linked project unless -p is passed.

Examples:
  $ stackblaze projects rename "Web shop" -p shop
  $ stackblaze projects rename --clear -p shop
```

## projects iac

```text
Usage: stackblaze projects iac [options] [state]

Turn Infrastructure as Code on or off for the project (on | off | status)

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

apply and plan are refused while IaC is off, and projects created with
`projects create` start with it off. Uses the linked project unless -p is
passed. Same switch as Project Settings → General → Infrastructure as Code.

Examples:
  $ stackblaze projects iac              # show
  $ stackblaze projects iac on -p demo
  $ stackblaze projects iac off
```
