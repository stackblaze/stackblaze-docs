```text
Usage: stackblaze down [options]

Pause the linked app: stop all its pods (web, worker, cron jobs) but keep the
deployment

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  -a, --app <name>       App name
  --json                 Output JSON (same as -o json) (default: false)
  -y, --yes              Skip confirmation prompt (default: false)
  -m, --message <text>   Reason, recorded in the deployment history
  --build <name>         Also delete a git build/deployment by name
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

Pausing keeps the deployment, its instance and autoscaling settings, volumes
and add-ons. Compute stops billing; volumes and add-ons keep running (and
billing). Builds still run while paused: a git push updates the image, but no
pods start until you resume. Visitors see a "paused by its owner" page.

`stackblaze down` does not remove the deployment; it only pauses it. Bring it back with `stackblaze resume` (or `stackblaze up --resume`).
To delete the app instead, use `stackblaze apps delete`.

Examples:
  $ stackblaze down
  $ stackblaze down -y -m "pausing over the weekend"
  $ stackblaze resume
```
