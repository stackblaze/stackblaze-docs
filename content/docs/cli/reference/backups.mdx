```text
Usage: stackblaze backups|backup [options] [command]

Recovery points of a project environment: back up, restore as new databases and

Options:
  --api-url <url>           StackBlaze API base URL (env STACKBLAZE_API_URL)

                            "json")

Commands:
  list|ls [options]         List recovery points: time, status, what each holds
                            (everything or partial)
  show|get [options] <id>   What a recovery point holds (databases, volumes)
                            and what a restore would create
  create [options]          Back the environment up now, or only --only
                            <service|database> (a partial recovery point)
  restore [options] <id>    Restore a recovery point as NEW databases and
                            volumes (everything, or chosen items); nothing
                            running changes
  status [options]          The running restore (new databases / volumes being
                            created), or one that ended in the last 10 minutes
  schedule [options]        Show the environment's backup schedule (read only;
                            set it in the dashboard)
  delete|rm [options] <id>  Delete a recovery point and its data (confirm by
                            typing its id)
```

## backups create

```text
Usage: stackblaze backups create [options]

Back the environment up now, or only --only <service|database> (a partial
recovery point)

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  --json                 Output JSON (same as -o json) (default: false)
  --only <name>          Back up only this service or database (repeatable, or
                         comma-separated)
  --wait                 Wait until the backup and its database dumps are done
                         (exit 1 if it fails) (default: false)
  --timeout <seconds>    Max --wait time (default: 1800)
  --ci                   Output NDJSON events (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

A recovery point holds the environment's services, its volumes and a dump of
each database. --only makes a PARTIAL point with the data of just the named
services (their volumes) and databases. Never creates or changes a schedule.

Examples:
  $ stackblaze backups create --wait
  $ stackblaze backups create --only web --only web-postgresql -e staging
```

### Example

Take a partial recovery point of just the `whiteboard` app and its database, and wait until the dump is saved:

```sh
stackblaze backups create -p github-demo-cw8z -e dev --only whiteboard,whiteboard-8stj-postgresql-6bt2 --wait
```


The app has no volumes, so the point holds only the database.

## backups restore

```text
Usage: stackblaze backups restore [options] <id>

Restore a recovery point as NEW databases and volumes (everything, or chosen
items); nothing running changes

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  -e, --env <name>       Environment name (default: production)
  --json                 Output JSON (same as -o json) (default: false)
  --database <name>      Only this database (repeatable, or comma-separated)
  --volume <name>        Only this volume, by PVC or volume name (repeatable,
                         or comma-separated)
  --copy                 No longer needed (every restore creates new databases
                         and volumes); accepted for compatibility (default:
                         false)
  -y, --yes              Accepted for compatibility (a restore needs no
                         confirmation: nothing running changes) (default:
                         false)
  --wait                 Wait until the new databases and volumes are ready
                         (exit 1 if the restore fails) (default: false)
  --timeout <seconds>    Max --wait time (default: 2700)
  --ci                   Output NDJSON events (default: false)
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

<id> is a recovery point from `stackblaze backups list` (a unique prefix
works), or `latest`.

A restore ALWAYS creates NEW databases and volumes under new names. The
running environment is never touched: you choose when to connect your app to
the new ones (`stackblaze apps update`, or the dashboard) and when to delete
the old ones. Both are billed until then.

  (no item flags)          new copies of everything in the point.
  --database / --volume    new copies of only those items.

Examples:
  $ stackblaze backups restore latest --database web-postgresql
  $ stackblaze backups restore velero-demo-production-20261103 --volume data
  $ stackblaze backups restore latest --wait -e staging
```

### Example

Restore only the database from the newest recovery point, as a new database. Nothing running changes:

```sh
stackblaze backups restore latest --database whiteboard-8stj-postgresql-6bt2 -p github-demo-cw8z -e dev
```

```text
OK Restore b55c0774-27d9-4e7f-b893-c73d874d7282 started for github-demo-cw8z/dev
Follow it with `stackblaze backups status -p github-demo-cw8z -e dev` (or pass --wait).
```
