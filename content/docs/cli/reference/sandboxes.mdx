Usage: stackblaze sandboxes|sandbox [options] [command]

Developer sandboxes: disposable VMs with a shell and VS Code in a project
environment

Options:
  -h, --help                    Print help

Commands:
  list|ls [options]             List the sandboxes of a project environment
  sizes|capabilities [options]  Machine sizes (vCPU / memory / disk) and which
                                your plan allows
  create [options] [name]       Create a sandbox (boots the agent image in a
                                VM); --for <app> attaches a service's volumes
                                and add-ons

                                VS Code URL
  delete|rm [options] <name>    Delete a sandbox, its workspace disk and
                                checkpoints (confirm by typing its name)
  sleep [options] <name>        Put a sandbox to sleep (scale to zero; disk and
                                volumes stay)
  wake [options] <name>         Boot a sleeping sandbox again
  resize [options] <name>       Change the machine size (the VM restarts; the
                                disk grows with the size, never shrinks)
  ssh [options] <name>          Open a shell in the sandbox VM (Console must be
                                enabled for your organization)
  ide [options] <name>          Print a short-lived sign-in link for the
                                sandbox's browser VS Code
  help [command]                Print this message or the help of the given
                                subcommand(s)

## sandboxes create

```text
Usage: stackblaze sandboxes create [options] [name]

Create a sandbox (boots the agent image in a VM); --for <app> attaches a
service's volumes and add-ons

Options:
  --api-url <url>        StackBlaze API base URL (env STACKBLAZE_API_URL)
  --token <token>        API token, sb_pat_... (env STACKBLAZE_TOKEN)
  -p, --project <name>   Project name
  --phase <name>         Environment name (default: production)
  --json                 Output JSON (same as -o json) (default: false)
  --size <id>            Machine size from `sandboxes sizes`, which also sets
                         the disk (default: the platform default)
  --image <ref>          Container image to boot instead of the default agent
                         image
  --for <app>            Develop this service: its volumes and add-ons are
                         attached
  --read-only            With --for: mount the service's volumes read-only
                         (default: false)
  --env <pair>           KEY=value in the sandbox (repeatable; not with --for).
                         The environment is --phase here
  -o, --output <format>  Output format: text or json (choices: "text", "json")
  -h, --help             Print help

Examples:
  $ stackblaze sandboxes create                  # random name, default size
  $ stackblaze sandboxes create scratch --size 4x --phase staging   # 4 vCPU · 8 GiB · 40 GiB disk
  $ stackblaze sandboxes create --for web        # a dev box on web's data
  $ stackblaze sandboxes ssh scratch
May be disabled by your platform admin.
```

### Example

Create a small sandbox called `scratch` in the `dev` environment. The environment flag is `--phase` here (`--env` sets variables inside the sandbox). The name gets a suffix:

```sh
stackblaze sandboxes create scratch --size 1x -p github-demo-cw8z --phase dev
```

```text
OK Sandbox scratch-mkwl is booting in github-demo-cw8z/dev (size 1x, 10Gi disk)
Shell: stackblaze sandboxes ssh scratch-mkwl -p github-demo-cw8z -e dev
VS Code: stackblaze sandboxes ide scratch-mkwl
```
